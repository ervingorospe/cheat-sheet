App Documentation

Cheat Library — AI Study Notes

A mobile app (Expo + React Native) that turns screenshots and photos into structured study notes with Gemini, organized in nested folders and backed by Supabase. This page covers what it does, its data model, and its core flows. Written from the current code and migrations — re-check it if they change.

Summary Tech Stack Structure Data Model (ERD) Core Flows Setup Roadmap

01 What the app does

Snap or pick images, get notes back, keep them organized and searchable. Every row is private to its owner.

AI note generation

One or more images become a title, summary, key points and a suggested documentation topic.

Editable notes

Edit title, content, key points, documentation links and image links. Paginated list with skeleton loading.

Nested folders

Folders inside folders, with cycle prevention in the database. Deleting shows how many folders and notes are affected first.

Search

Debounced search across notes, plus a home screen with stats, quick actions and recent notes.

Auth

Email/password with “remember me”, plus Google and Facebook OAuth. Routes are guarded by session.

Profile

Edit name, upload an avatar, and change password (only for accounts that use password auth).

04 Data model (ERD)

From supabase/migrations. All three public tables have RLS: users can only touch rows where their id matches.

erDiagram
    AUTH_USERS {
        uuid id PK
        string email
    }
    PROFILES {
        uuid id PK
        string email
        string first_name
        string last_name
        string avatar_url
        bool is_active
    }
    FOLDERS {
        uuid id PK
        uuid user_id FK
        uuid parent_folder_id FK
        string name
    }
    NOTES {
        uuid id PK
        uuid user_id FK
        uuid folder_id FK
        string title
        string content
        jsonb key_points
        jsonb doc_links
        jsonb image_links
    }
    AUTH_USERS ||--|| PROFILES : "trigger creates"
    AUTH_USERS ||--o{ FOLDERS : owns
    AUTH_USERS ||--o{ NOTES : owns
    FOLDERS ||--o{ FOLDERS : "parent of"
    FOLDERS ||--o{ NOTES : contains

Deletes: user → profile, folders, notes cascade. Deleting a folder cascades to subfolders, but notes get folder_id = null (set null). Storage buckets note-images and avatars are not cascaded and must be cleaned separately.

ObjectWhat it does
handle_new_userCreates a profile on every new auth user (password or OAuth), splitting full_name
prevent_folder_cycleRejects self-parenting and moves that would create a loop
get_descendant_folder_ids()Recursive query returning a folder and all descendants
set_updated_atKeeps updated_at current on every table
idx_notes_user_folder · idx_folders_user_parentIndexes for the common list queries

05 Core flows

The journeys that define how the app is used.

Flow 1 Sign-in & route guard

Password and OAuth both end in a Supabase session; the guard then swaps the visible route groups. The profile row is created by a database trigger, not by the app.

flowchart TD
    A["App launch"] --> B["AuthProvider restores session"]
    B --> C{"Session?"}
    C -- No --> D["(auth) screens"]
    C -- Yes --> E["(tabs) + (main) screens"]
    D --> F{"Method"}
    F -- "Email + password" --> G["signInWithPassword
(remember-me preference stored)"]
    F -- "Sign up" --> H["signUpWithPassword"]
    F -- "Google / Facebook" --> I["signInWithOAuth
(expo-auth-session)"]
    H --> J[("auth.users row")]
    I --> J
    J --> K["Trigger handle_new_user
creates profiles row"]
    G --> L["Session set"]
    K --> L
    L --> E
Flow 2 AI note generation

Generation and image upload run in parallel. If the user cancels or either side fails, uploaded images are deleted so nothing is orphaned.

flowchart TD
    A["Pick from library or camera"] --> B["useCreateNoteFlow"]
    B --> C["generate-notes edge function
(base64 + mimeType items)"]
    B --> D["uploadNoteImage
to note-images bucket"]
    C --> E["Gemini returns title, summary,
keyPoints, suggestedTopic"]
    E --> F{"Cancelled or
failed?"}
    D --> F
    F -- Yes --> G["Delete uploaded images
+ toast error"]
    F -- No --> H["createNote
(optionally in a folder)"]
    H --> I{"Saved?"}
    I -- No --> G
    I -- Yes --> J["Open note detail"]
Flow 3 Folder management

Moves are validated in the database, so the client cannot create a cycle even by accident. Delete always shows its impact first.

flowchart TD
    A["Create folder
(name, optional parent)"] --> B[("folders row")]
    B --> C["Rename"]
    B --> D["Move folder"]
    D --> E{"Trigger
prevent_folder_cycle"}

Flow 4 Note edit, move & delete

All edits go through updateNote; deleting a note also removes its stored images.

06 Setup & deployment

pnpm install
pnpm start       # Expo dev server
pnpm ios         # iOS dev build
pnpm android     # Android dev build
pnpm rebuild     # expo prebuild --clean
  • App config — Supabase project URL and publishable key only; both are safe to ship in the client.
  • Edge function — generate-notes reads GEMINI_API_KEY from Supabase secrets. It retries up to 2 times with backoff.
  • Database — migrations in supabase/migrations, applied in timestamp order.
  • Builds — EAS profiles in eas.json.
  • Secrets — never commit DB passwords, OAuth client secrets or API keys.
